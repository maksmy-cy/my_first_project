# Ответы на вопросы — ПР №9 «JavaScript: базовые алгоритмы»

**1. Разница между O(n) и O(n²). Примеры.**
O(n) — время растёт линейно: при увеличении данных вдвое работа удваивается (поиск максимума, `removeDuplicates` через Set, один проход по массиву). O(n²) — время растёт квадратично: вдвое больше данных — вчетверо больше операций, обычно из-за вложенных циклов (пузырьковая сортировка, сравнение всех пар элементов). На 1000 элементов это ~1000 против ~1 000 000 операций.

**2. Как работает бинарный поиск и почему O(log n)?**
Работает только на отсортированном массиве. Берём средний элемент: если он равен искомому — готово, если меньше — продолжаем в правой половине, если больше — в левой. Каждый шаг отбрасывает половину диапазона, поэтому после k шагов остаётся n / 2ᵏ элементов; поиск закончится, когда останется 1 элемент, то есть при k ≈ log₂n. Для миллиона элементов — около 20 сравнений.

**3. Плюсы и минусы пузырьковой сортировки.**
Плюсы: очень простая, сортирует «на месте» (O(1) доп. памяти), устойчивая, при флаге `swapped` на уже отсортированных данных работает за O(n). Минусы: O(n²) в среднем и худшем случае, поэтому на больших массивах она многократно медленнее быстрой сортировки, сортировки слиянием или встроенной `Array.prototype.sort` (O(n log n)). Применима для обучения и очень маленьких массивов.

**4. Как оптимизировать проверку на простоту для больших чисел?**
Проверять делители только до √n; сразу отсеивать чётные и кратные 3, дальше перебирать только числа вида 6k ± 1 (так сделано в `isPrime` — это в ~3 раза меньше делений, чем перебор до n). Для очень больших чисел применяют решето Эратосфена (когда нужно много простых подряд) или вероятностные тесты Миллера — Рабина, а для чисел больше 2⁵³ — BigInt.

**5. Рекурсивная и итеративная реализации Фибоначчи.**
Итеративная считает числа в цикле и хранит два предыдущих значения: O(n) времени, O(1) памяти (O(n) если нужен весь массив). Наивная рекурсия `fib(n) = fib(n-1) + fib(n-2)` пересчитывает одни и те же подзадачи и работает за O(2ⁿ), а также рискует переполнить стек вызовов. Рекурсию можно ускорить мемоизацией (до O(n)), но итерация всё равно проще и безопаснее по памяти.

**6. Какие методы отладки использовались?**
`console.log` и `console.table` для промежуточных значений, точки останова (breakpoints) и пошаговое выполнение в DevTools, проверка крайних случаев вручную в консоли, а главное — автотесты в `tests.js`: они сразу показывают, какой именно случай сломался и какое значение получено вместо ожидаемого.

**7. Как работает алгоритм Евклида и почему он эффективен?**
НОД(a, b) = НОД(b, a mod b); повторяем, пока остаток не станет 0 — последнее ненулевое число и есть НОД. Это работает, потому что любой общий делитель a и b делит и остаток a mod b. Эффективность: остаток уменьшается минимум вдвое за каждые два шага, поэтому сложность O(log(min(a, b))). Перебор делителей потребовал бы O(min(a, b)).

**8. Edge cases при работе с массивами.**
Пустой массив (`findMax([])`, `binarySearch([], x)`), массив из одного элемента, все элементы одинаковые, уже отсортированный и обратно отсортированный массив, дубликаты, отрицательные числа, элементы разных типов (`'10'` и `9`), `NaN`, `undefined`, очень большие массивы, а также мутация исходных данных (`bubbleSort` работает с копией).

**9. Как улучшить удаление дубликатов для больших массивов?**
Вместо вложенных циклов с `indexOf` (O(n²)) использовать `Set` или `Map` — O(n) по времени. Для сортируемых данных можно отсортировать массив (O(n log n)) и пройти один раз, сравнивая соседей без дополнительной памяти. Для очень больших данных — обработка потоком/пакетами, для объектов — ключ (id) вместо сравнения по ссылке.

**10. Какие принципы чистого кода применены?**
Осмысленные имена функций и переменных; одна функция — одна задача; отсутствие «магических» значений (наборы символов вынесены в константы); ранние возвраты для крайних случаев вместо глубокой вложенности; проверка входных данных; комментарии JSDoc с описанием и сложностью; отсутствие мутации входных аргументов; единый стиль форматирования и `'use strict'`; тесты для каждой функции, включая граничные случаи.
