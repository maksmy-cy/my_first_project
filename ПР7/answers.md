# Ответы на вопросы — ПР №7 «Вёрстка и валидация форм»

**1. Какие HTML5-атрибуты используются для клиентской валидации?**
`required` (поле обязательно), `minlength`/`maxlength` (длина текста), `min`/`max` (границы чисел и дат), `pattern` (регулярное выражение), `type` (`email`, `tel`, `url`, `number`, `date` — браузер проверяет формат), `step`. Браузер сам блокирует отправку формы и показывает подсказку, а также выставляет псевдоклассы `:valid`/`:invalid`.

**2. Разница между `novalidate` и отключением валидации через JavaScript?**
`novalidate` на `<form>` говорит браузеру не запускать встроенную проверку при отправке: подсказки не показываются, но атрибуты (`required`, `pattern`) остаются в разметке, работают псевдоклассы и API (`checkValidity()`, `validity`). Отключение «через JS» (например, `preventDefault()` на submit) просто отменяет отправку или подменяет логику, а встроенная проверка при этом всё равно выполнится до события submit. В проекте используется `novalidate` + собственная проверка, чтобы получить единый вид сообщений и управлять доступностью.

**3. Как связать `<label>` с полем и почему это важно?**
Двумя способами: `<label for="email">` + `<input id="email">` или вложить input внутрь label. Важно, потому что скринридер зачитывает название поля при фокусе, а клик по подписи фокусирует поле (увеличивается область нажатия, особенно для чекбоксов и радио). Placeholder заменой label быть не может: он исчезает при вводе и плохо читается скринридерами.

**4. Какие типы `input` подходят для разных данных?**
`email` — почта (мобильная клавиатура с @), `tel` — телефон (цифровая клавиатура), `password` — пароль, `url` — ссылка, `number` — числа со шагом, `date` — дата, `search`, `checkbox` — флаги, `radio` — выбор одного из нескольких. Для телефона не используют `number`: ведущий «+» и пробелы не поддерживаются, а стрелки счётчика бесполезны.

**5. Как работает `pattern` и когда его использовать?**
Значение атрибута — регулярное выражение, которому должно целиком соответствовать значение поля (неявно `^(?:…)$`). Применяется для текстовых типов (`text`, `tel`, `email`, `password`, `search`, `url`). Подходит для форматов с жёсткой структурой: телефон, индекс, артикул. Для сложных правил (сравнение полей, возраст по дате) он не годится — нужен JS. Желательно добавлять `title` или видимую подсказку с форматом.

**6. Какие события JS используются для валидации в реальном времени?**
`input` — срабатывает при каждом изменении значения (даёт мгновенную реакцию, но агрессивно показывать ошибки на первом символе не стоит); `blur` — потеря фокуса (лучший момент для первой проверки); `change` — для select, радио и чекбоксов; `submit` — итоговая проверка всей формы. В проекте ошибка впервые появляется на `blur`, а дальше обновляется на `input`, чтобы не ругаться на пользователя, пока он ещё печатает.

**7. Как обеспечить доступность сообщений об ошибках для скринридеров?**
Связать сообщение с полем через `aria-describedby`, выставлять `aria-invalid="true"`, помещать текст ошибки в область с `aria-live="polite"` (или `role="alert"` для сводки при отправке), после неудачной отправки переводить фокус на первое ошибочное поле. Нельзя передавать информацию только цветом — ошибку дублируем текстом. Обязательные поля помечаем `required` и/или `aria-required`.

**8. Преимущества `fieldset` и `legend`?**
Семантически объединяют связанные поля (группа радио, адрес, контакты). Скринридер при входе в группу зачитывает legend («Пол, группа из трёх переключателей»), что даёт контекст. Есть базовая визуальная группировка и возможность отключить сразу всю группу атрибутом `disabled`. Для радиокнопок использование `fieldset`/`legend` практически обязательно.

**9. Как реализовать кастомную валидацию (подтверждение пароля)?**
Написать функцию, которая сравнивает значения двух полей (`passwordConfirm.value !== password.value`), вызывать её на `input`/`blur`/`submit`, показывать сообщение и выставлять `aria-invalid`. Также нужно перепроверять подтверждение при изменении основного пароля. Альтернатива — стандартный API: `input.setCustomValidity('Пароли не совпадают')` (пустая строка — поле валидно) и `reportValidity()`.

**10. Какие методы CSS показывают состояния валидности?**
Псевдоклассы `:valid`, `:invalid`, `:required`, `:optional`, `:focus`, `:focus-visible`, `:user-invalid` (срабатывает только после взаимодействия пользователя), `:placeholder-shown`. Проблема голого `:invalid` — поля подсвечиваются красным ещё до ввода, поэтому в проекте состояния задаются классами `.is-valid` / `.is-invalid`, которые JS добавляет после взаимодействия. Дополнительно используются `border-color`, фон, `outline` для фокуса и `accent-color` для чекбоксов.
