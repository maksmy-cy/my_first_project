# Ответы на вопросы для самоконтроля (ПР10)

**1. Function Declaration и Function Expression: hoisting**

Function Declaration (`function f() {}`) поднимается целиком: её можно вызвать до строки объявления. Function Expression (`const f = function () {}` или стрелочная) — это обычное присваивание значения переменной. Переменная `var` поднимается как `undefined` (вызов даст `TypeError: f is not a function`), а `let`/`const` попадают в «временную мёртвую зону» и до строки объявления выбрасывают `ReferenceError`. Кроме того, Function Expression может быть анонимным и используется как значение (callback, возврат из функции).

**2. Rest parameters и `arguments`**

`...args` — настоящий массив, содержащий «остаток» аргументов; у него есть все методы массива (`map`, `filter`, `reduce`). `arguments` — псевдомассив (есть `length` и индексы, но нет методов массива), он недоступен в стрелочных функциях и содержит все аргументы, а не только «оставшиеся». Rest можно комбинировать с именованными параметрами (`function f(a, ...rest)`), он явно виден в сигнатуре, поэтому код читается лучше. В коде: `sum(...numbers)`, `compose(...functions)`.

**3. Замыкание и лексическая область видимости**

Лексическая область видимости означает, что доступ к переменным определяется местом, где функция *написана*, а не где вызвана. Замыкание — это функция вместе со ссылкой на внешнее лексическое окружение, в котором она создана; она «помнит» эти переменные даже после завершения внешней функции. В работе: `secretMessage` хранит `password` и `message` в замыкании — снаружи прочитать их нельзя; `memoize` хранит кэш, `debounce` — таймер, `throttle` — время последнего вызова.

**4. Рекурсия или итерация**

Рекурсия естественна для вложенных и древовидных структур (обход DOM, `flattenDeep`, JSON, файловая система), задач «разделяй и властвуй», где определение само рекурсивно (факториал, комбинаторика). Плюсы: короткий и выразительный код. Минусы: каждый вызов занимает место в стеке (риск `RangeError: Maximum call stack size exceeded` на больших глубинах), накладные расходы на вызовы, JS не гарантирует оптимизацию хвостовой рекурсии. Итерация (циклы) эффективнее по памяти и скорости, подходит для линейных задач и больших объёмов данных, но для деревьев требует явного стека и становится громоздкой. Правило: плоские данные и большие размеры — цикл; вложенные структуры и ограниченная глубина — рекурсия (при необходимости с мемоизацией).

**5. Функции высшего порядка**

Это функции, которые принимают другие функции как аргументы и/или возвращают функции. Это возможно, потому что в JS функции — значения первого класса. Встроенные методы массивов: `map`, `filter`, `reduce`, `reduceRight`, `forEach`, `find`, `findIndex`, `some`, `every`, `flatMap`, `sort` (с компаратором). В работе: `compose`, `curry`, `memoize`, `debounce`, `throttle` принимают и возвращают функции; `myMap`, `myFilter`, `myReduce` принимают callback.

**6. Каррирование**

Каррирование превращает функцию от нескольких аргументов в цепочку функций от одного (или части) аргумента: `f(a, b, c)` → `f(a)(b)(c)`. Преимущества: частичное применение (`const add10 = curry(add)(10)`), переиспользование «настроенных» функций, удобная композиция (`compose`/`pipe` работают с функциями одного аргумента), более декларативный код. Недостатки: небольшие накладные расходы и неочевидность для читателя, а для функций с необязательными/rest-параметрами `fn.length` работает некорректно.

**7. Мемоизация**

Мемоизация — кэширование результата функции по набору аргументов: при повторном вызове с теми же аргументами результат берётся из кэша, а не вычисляется заново. Эффективна для **чистых** функций (результат зависит только от аргументов, нет побочных эффектов), для дорогих вычислений и при повторяющихся входных данных: рекурсивные задачи с перекрывающимися подзадачами (числа Фибоначчи: из O(2ⁿ) в O(n)), парсинг, тяжёлые преобразования. Неэффективна/опасна: для нечистых функций (время, случайность, запросы), при почти всегда разных аргументах, при больших кэшах без очистки (утечка памяти — решения: лимит размера, `WeakMap`, `clear()`).

**8. Debounce и throttle**

*Debounce* откладывает вызов, пока новые вызовы не прекратятся на `delay` мс: из серии вызовов выполняется один — после паузы. Применение: поиск при вводе текста, валидация формы, сохранение черновика, `resize` (когда нужен только итог). *Throttle* гарантирует, что функция выполнится не чаще раза в `interval` мс, и во время серии вызовов она продолжает срабатывать регулярно. Применение: `scroll`, `mousemove`, drag-and-drop, анимации, кнопки «лайк» (когда нужна реакция «по ходу»). Коротко: debounce — «подожди, пока закончат», throttle — «не чаще, чем раз в N мс».

**9. Функции-генераторы (`function*`)**

Обычная функция выполняется до конца и возвращает одно значение. Генератор при вызове возвращает итератор и не выполняет тело сразу; выполнение идёт по шагам: `next()` запускает код до очередного `yield`, отдаёт значение и приостанавливается, сохраняя локальное состояние. Генераторы ленивы (можно описывать бесконечные последовательности, например `function* ids() { let i = 0; while (true) yield i++; }`), работают с `for...of` и spread, умеют принимать значения через `next(value)`, и лежат в основе async-итераций. Применяются для ленивых вычислений, пагинации, обхода деревьев.

**10. Принципы функционального программирования в работе**

- **Чистые функции** (`sum`, `compose`, `createValidator`): результат зависит только от аргументов, нет побочных эффектов, их легко тестировать.
- **Неизменяемость**: `myMap`/`myFilter` возвращают новые массивы, не мутируя исходные.
- **Функции — значения первого класса и функции высшего порядка**: `compose`, `curry`, `memoize`, `debounce`, `throttle`.
- **Замыкания** для инкапсуляции состояния (`secretMessage`, кэш в `memoize`).
- **Композиция и каррирование** для сборки сложного поведения из простых функций.
- **Рекурсия** вместо изменяемых счётчиков (`factorial`, `flattenDeep`).

Преимущества: предсказуемость, простое тестирование, переиспользование, меньше багов из-за общего изменяемого состояния, код проще рассуждать и комбинировать.
