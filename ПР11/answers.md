# Ответы на вопросы для самоконтроля (ПР №11)

## 1. В чем разница между `innerHTML` и `textContent` и когда использовать каждый?

- `textContent` читает и записывает **только текст**. Всё, что записано, воспринимается как обычные символы: `<b>` останется строкой `<b>`. Работает быстро и безопасно.
- `innerHTML` читает и записывает **HTML-разметку**. Строка разбирается парсером и превращается в элементы. Это удобно для вставки готовых фрагментов, но если в строке есть пользовательский ввод, возможна **XSS-атака** (например, `<img src=x onerror=...>`). Кроме того, при записи все старые дочерние узлы пересоздаются, и обработчики на них теряются.

**Правило:** для вывода текста, особенно пользовательского, — `textContent`. `innerHTML` — только для доверенной, заранее известной разметки. В работе все данные из полей ввода выводятся через `textContent`.

## 2. Как работает делегирование событий и какие у него преимущества?

События **всплывают** от элемента вверх по дереву. Поэтому вместо отдельного обработчика на каждый дочерний элемент вешают **один** на общего родителя и внутри определяют, на каком элементе произошло событие (`event.target`, обычно через `target.closest('.delete-btn')`).

Преимущества:
- работает для элементов, которые **добавят позже** (новые `li` в списке не нужно подписывать отдельно);
- меньше обработчиков — меньше памяти и проще код;
- не нужно снимать обработчики при удалении элементов.

В работе: один обработчик `click` на `#dynamic-list` обрабатывает кнопки «Удалить» всех элементов.

## 3. Какие методы поиска элементов есть и в чем разница между `getElementById`, `querySelector`, `querySelectorAll`?

- `getElementById(id)` — ищет по `id`, возвращает один элемент или `null`. Самый быстрый.
- `querySelector(selector)` — принимает любой CSS-селектор, возвращает **первый** подходящий элемент или `null`.
- `querySelectorAll(selector)` — возвращает **статичную** `NodeList` всех подходящих элементов (пустую, если ничего нет). Можно использовать `forEach`.

Есть и другие: `getElementsByClassName` и `getElementsByTagName` возвращают **живую** `HTMLCollection`, которая обновляется вместе с DOM. Также доступны `closest()`, `matches()` и навигация `parentElement`, `children`, `nextElementSibling`.

## 4. Как предотвратить стандартное поведение элемента и когда это нужно?

Вызвать `event.preventDefault()` в обработчике. Событие при этом продолжает всплывать, отменяется только действие браузера по умолчанию.

Нужно, например:
- при отправке формы (`submit`), чтобы страница не перезагружалась и данные обрабатывались в JavaScript (так сделано в `handleFormSubmit`);
- при клике по ссылке `<a>`, если переход выполняется скриптом;
- при перетаскивании, контекстном меню, отмене нажатия клавиши и т. п.

Событие должно быть отменяемым (`event.cancelable`), а в `addEventListener` для `touch`/`wheel` с флагом `passive: true` `preventDefault()` не сработает.

## 5. В чем разница между `classList.add()` и `className`?

- `className` — это **вся строка** атрибута `class`. Присваивание `el.className = 'a'` **заменяет** все существующие классы, а для добавления приходится вручную склеивать строки с пробелами.
- `classList` — объект `DOMTokenList` с методами `add`, `remove`, `toggle`, `contains`, `replace`. Он меняет только указанные классы, не создаёт дубликатов и не требует работать со строкой.

`classList` безопаснее и читаемее, поэтому используется по умолчанию (например, `classList.toggle('active-style')`). `className` удобен, когда нужно задать или прочитать всю строку целиком.

## 6. Как создать элемент и добавить его в DOM разными способами? Какой эффективнее?

Создание: `document.createElement('div')`, `cloneNode(true)`, `<template>`, либо запись строки в `innerHTML` / вызов `insertAdjacentHTML`.

Вставка: `appendChild`, `append` / `prepend`, `before` / `after`, `insertBefore`, `insertAdjacentElement`, `replaceWith`, `replaceChildren`.

Эффективность:
- Для одного элемента разница незаметна. Предпочтительны `createElement` + `textContent` + `append`: безопасно и понятно.
- Для **многих** элементов эффективнее собрать их в `DocumentFragment` (или в один родитель вне документа) и вставить **одной** операцией — тогда браузер пересчитывает раскладку один раз (так сделан `createList`).
- `innerHTML +=` в цикле — худший вариант: каждый раз пересоздаёт всё содержимое.

## 7. Что такое всплытие событий (event bubbling) и как работает `stopPropagation()`?

Сначала событие идёт от `window` вниз к цели (фаза **погружения**, capturing), затем срабатывает на самой цели, и после этого **всплывает** вверх через всех родителей до `document` (фаза всплытия). Поэтому клик по кнопке виден и обработчикам на её родителях.

`event.stopPropagation()` останавливает дальнейшее продвижение события по дереву: родительские обработчики не вызываются. Остальные обработчики на том же элементе всё равно выполнятся; чтобы остановить и их, нужен `stopImmediatePropagation()`.

Использовать нужно осторожно: оно ломает делегирование и сторонние слушатели на родителях (например, аналитику или закрытие выпадающих меню). Часто достаточно проверки `event.target`.

## 8. Как получить данные из формы и в чем разница между способами сбора?

Способы:
1. **По элементам:** `form.elements['name'].value` или `document.getElementById('user-name').value` — явно, но нужно перечислять поля вручную (способ из работы).
2. **`new FormData(form)`** — собирает все поля с атрибутом `name` автоматически; подходит для отправки через `fetch`. Читается через `get('name')`, `entries()`, а в простой объект превращается через `Object.fromEntries(formData)`.
3. **`form.elements` в цикле** — для динамических форм.

Различия: `FormData` учитывает только поля с `name` и не включает отключённые (`disabled`) поля и невыбранные чекбоксы; кроме того, умеет работать с файлами и повторяющимися ключами (`getAll`). Ручной сбор даёт полный контроль над преобразованием и обрезкой данных (`trim`, `Number`). Значения всегда строки, поэтому числа нужно приводить вручную.

## 9. Какие события используются для ввода данных и в чем разница между `input`, `change`, `keyup`?

- `input` — срабатывает **сразу при любом изменении значения**: ввод, вставка, удаление, голосовой ввод, перетаскивание текста. Лучший выбор для «живого» отображения (используется в `setupInputDisplay`).
- `change` — срабатывает, когда значение **зафиксировано**: для текстового поля — при потере фокуса (или Enter) *и только если значение изменилось*; для `select`, чекбоксов и радиокнопок — сразу при выборе.
- `keyup` — срабатывает при **отпускании клавиши**. Привязан к клавише, а не к изменению значения: не сработает при вставке мышью или автозаполнении и срабатывает на клавиши, не меняющие текст (стрелки, Shift). Годится для обработки горячих клавиш, но не для отслеживания значения.

Есть ещё `keydown` (нажатие, повторяется при удержании), `focus` / `blur` и `paste`.

## 10. Как оптимизировать производительность при частых манипуляциях с DOM?

- **Минимизировать число обращений к DOM:** кешировать найденные элементы в переменные, не искать их в цикле.
- **Собирать изменения пачкой:** `DocumentFragment`, построение поддерева вне документа и вставка одной операцией; `replaceChildren` для замены содержимого.
- **Не смешивать чтение и запись геометрии** (`offsetWidth`, `getBoundingClientRect` и запись стилей чередой), иначе браузер многократно пересчитывает раскладку (layout thrashing). Сначала читаем всё, потом пишем всё.
- **Менять классы, а не множество inline-стилей:** `classList.toggle` вместо десятка присваиваний `style.*`.
- **Анимировать через CSS** (`transform`, `opacity`, `transition`) — они не вызывают перерасчёт раскладки; для покадровой работы — `requestAnimationFrame`.
- **Делегирование событий** вместо сотен обработчиков; `debounce` / `throttle` для частых событий (`scroll`, `resize`, `input`).
- **Для больших списков** — виртуализация (рисуем только видимые элементы).
- Временно скрывать элемент (`display: none`) на время массовых правок и использовать `textContent` вместо `innerHTML`, когда разметка не нужна.
